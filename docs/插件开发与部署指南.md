# WeKnora 插件开发与部署指南

本文面向插件开发者和 WeKnora 系统管理员，适用于第一版外部插件协议 `weknora.plugin.v1`。外部插件是独立进程或容器，不链接 WeKnora 的数据库和 Redis，只通过 gRPC 与 `plugin-runtime` 交换被授权的数据。

## 1. 选择插件类型

一个插件可以声明一种或多种能力类型：

| 类型 | `spec.types` | Go SDK 处理器 | 用途 |
| --- | --- | --- | --- |
| 数据源 | `data_source` | `DataSourceHandler` | 从 GitHub、Confluence、目录等来源同步原始文档 |
| 文档解析器 | `document_parser` | `DocumentParserHandler` | 把原始文件转换为 Markdown 和附件 |
| 联网搜索 | `web_search` | `WebSearchHandler` | 把厂商搜索结果转换为统一结果 |
| 模型供应商 | `model_provider` | `ModelProviderHandler` | 提供模型发现、对话、向量和重排能力 |

第一版提供完整公共协议和 Go SDK，并用 GitHub 数据源插件演示完整安装与同步。开发数据源插件时，插件只返回原始文件；解析、分块、向量化、索引和删除仍由 WeKnora 完成。

## 2. 从模板开始

主仓库的 `sdk/plugin/go/template` 是最小数据源插件模板。复制到独立仓库后，至少修改：

1. `plugin.yaml` 中的插件 ID、版本、镜像、连接器类型、配置 Schema 和权限。
2. `main.go` 中的配置校验、资源发现和同步实现。
3. `Dockerfile` 中的模块路径和构建方式。

SDK 尚未单独发布模块版本时，可以让插件仓库与 WeKnora 主仓并列，并在插件的 `go.mod` 中临时使用：

```go
require github.com/Tencent/WeKnora v0.0.0

replace github.com/Tencent/WeKnora => ../WeKnora
```

生产发布应固定到包含对应协议和 SDK 的 WeKnora 版本，不应长期依赖未固定的本地源码。

## 3. 编写 plugin.yaml

```yaml
apiVersion: weknora.io/v1
kind: Plugin
metadata:
  id: io.example.datasource.demo
  name: 示例数据源
  description: 从示例服务同步文档
  version: 0.1.0
spec:
  protocolVersion: 1.0.0
  weknoraVersion: ">=0.2.0"
  image: ghcr.io/example/weknora-demo-plugin:0.1.0
  types: [data_source]
  capabilities: [incremental, deletion_sync, checkpoint_resume]
  connectorType: example_demo
  icon: database
  defaultTimeout: 2m
  config:
    schema:
      $schema: https://json-schema.org/draft/2020-12/schema
      type: object
      additionalProperties: false
      properties:
        endpoint:
          type: string
          title: 服务地址
        token:
          type: string
          title: 访问令牌
      required: [endpoint]
    secretFields: [token]
  permissions:
    network: true
    allowedHosts: [api.example.com]
    dataAccess: [document_content, document_metadata]
```

关键约束：

- `metadata.id` 是全局稳定的反向域名 ID，升级时不能改变。
- `metadata.version`、`protocolVersion` 使用语义化版本。
- 数据源插件必须提供唯一的 `connectorType`，创建的数据源实例使用该类型。
- `config.schema` 用于前端动态生成租户配置表单。
- `secretFields` 只能填写 Schema `properties` 中的顶层字段；这些字段进入 WeKnora 现有密钥存储，不会通过普通配置接口回显。
- `allowedHosts` 仅在 `network: true` 时有效。插件只能经运行时代理访问这些域名。
- `defaultTimeout` 是默认单次调用超时，系统管理员安装时可覆盖，上限为一小时。
- 清单中的 `image` 必须和安装时传入的镜像一致，避免清单与实际镜像被替换。

支持的数据访问声明为：`document_content`、`document_metadata`、`query_text` 和 `conversation`。只声明实现能力真正需要的数据。

## 4. 启动 SDK 服务

```go
manifest, err := plugin.ParseManifest(manifestYAML)
if err != nil {
    log.Fatal(err)
}

handler := &myDataSource{}
server, err := plugin.NewServer(manifest, plugin.ServerOptions{
    Lifecycle:  handler,
    DataSource: handler,
})
if err != nil {
    log.Fatal(err)
}

err = server.Serve(ctx, ":9000")
```

每个清单声明的类型都必须传入对应处理器。SDK 自动提供协议握手、健康检查、配置 JSON 校验、gRPC 注册和优雅停止。

四类处理器分别通过 `ServerOptions.DataSource`、`DocumentParser`、`WebSearch` 和 `ModelProvider` 注册。插件若需要自定义动态配置校验和健康信息，同时实现 `LifecycleHooks`。

## 5. 实现数据源同步

数据源处理器实现：

- `ListResources`：返回仓库、空间、目录等可选资源。无需选择层级时可以只返回一个根资源。
- `ResolveResourceAncestors`：恢复资源选择层级；平铺数据源可返回空。
- `Sync`：遍历远端变化并发送文档、删除和检查点事件。

`Sync` 中常用的发送方法：

```go
err := emitter.EmitDocument(plugin.Document{
    ExternalID:  "stable-source-id",
    Title:       "readme",
    FileName:    "README.md",
    ContentType: "text/markdown",
    Content:     rawBytes,
    SourceURL:   sourceURL,
    UpdatedAt:   updatedAt,
    Metadata:    map[string]string{"path": "README.md"},
})

err = emitter.EmitDelete("deleted-source-id")
err = emitter.Checkpoint(json.RawMessage(`{"version":1,"next":20}`))
```

实现时遵守以下规则：

- `ExternalID` 在同一个数据源实例内必须稳定且唯一，不能使用 WeKnora 内部文档 ID。
- `Content` 是原始文件内容，不在插件中分块、向量化或写知识库。
- 每完成一个可安全恢复的批次就发送完整游标。游标是插件自解释的 JSON，WeKnora 原样保存。
- 只有已完成的工作才能写进检查点；重复处理同一个事件必须安全。
- 远端删除使用与原文档相同的 `ExternalID` 发送删除事件。
- 及时检查 `ctx.Done()`，让超时和停机可以终止网络请求并从最近检查点恢复。
- 不在日志中打印完整配置、令牌或文档敏感内容。

## 6. 其他三类处理器

文档解析器通过 `ParseStream.RecvContent` 流式读取原始内容，再用 `EmitMetadata`、`EmitMarkdown` 和 `EmitAttachment` 返回统一结果，避免必须把大文件整体缓存在内存中。

联网搜索处理器接收查询、语言、条数和分页令牌，返回 `WebSearchOutput`。每条结果使用统一的标题、URL、摘要、来源、发布时间和字符串元数据。

模型供应商处理器实现 `ListModels`、`Chat`、`Embed` 和 `Rerank`。`Chat` 通过 `ChatEmitter` 流式发送增量内容；模型只应声明自身实际支持的能力。

## 7. 本地测试与构建

在 WeKnora 主仓中测试 SDK：

```bash
go test ./sdk/plugin/go/...
```

在独立插件仓中测试插件：

```bash
go test ./...
WEKNORA_PLUGIN_LISTEN=:9000 go run .
```

由于示例插件开发期使用同级 WeKnora 源码，构建 GitHub 示例镜像时传入命名构建上下文：

```bash
docker buildx build \
  --build-context weknora=../WeKnora \
  -t weknora-github-source-plugin:dev .
```

网络环境无法访问官方 Go 模块代理时，可在构建命令中增加
`--build-arg GOPROXY_ARG=https://goproxy.cn,direct`。

发布镜像时使用不可变版本标签，并让 `plugin.yaml` 的 `metadata.version`、`spec.image` 与镜像标签保持一致。

离线联调本机构建镜像时，可只给 `plugin-runtime` 设置
`WEKNORA_PLUGIN_IMAGE_PULL_POLICY=if-not-present`。运行时会先确认清单声明的镜像已存在于本机 Docker，存在时跳过远端拉取；生产环境应保留默认的 `always`。

## 8. 启用运行时并安装

生成主服务和运行时之间的共享令牌：

```bash
openssl rand -hex 32
```

写入 `.env`：

```dotenv
WEKNORA_PLUGIN_RUNTIME_ENABLED=true
WEKNORA_PLUGIN_RUNTIME_ADDR=plugin-runtime:9091
WEKNORA_PLUGIN_RUNTIME_AUTH_TOKEN=<上一步生成的随机值>
```

使用插件 profile 启动：

```bash
docker compose --profile plugins up -d --build
```

系统管理员进入“系统管理 → 插件”，粘贴 `plugin.yaml`，按需设置调用超时，依次执行安装和启用。启用数据源插件后，租户管理员可以在知识库的数据源编辑器中选择清单提供的连接器，配置实例并触发手动或定时同步。

也可以通过系统管理员 JWT 调用：

```text
GET    /api/v1/system/admin/plugins
POST   /api/v1/system/admin/plugins
GET    /api/v1/system/admin/plugins/:id
PUT    /api/v1/system/admin/plugins/:id
POST   /api/v1/system/admin/plugins/:id/enable
POST   /api/v1/system/admin/plugins/:id/disable
POST   /api/v1/system/admin/plugins/:id/health
DELETE /api/v1/system/admin/plugins/:id
```

安装请求体为：

```json
{
  "manifest_yaml": "完整 plugin.yaml 文本",
  "image": "ghcr.io/example/weknora-demo-plugin:0.1.0",
  "call_timeout_seconds": 120
}
```

## 9. 升级与卸载

升级清单必须保持相同插件 ID 和 `connectorType`，新版本必须高于当前版本。升级由运行时先启动并验证新容器；失败时保留旧版本。租户数据源配置和同步游标保存在 WeKnora 中，不随插件容器替换而丢失。

卸载前必须先禁用插件，并删除所有仍引用该 `connectorType` 的数据源实例。内置插件只在统一列表中展示，不能通过外部运行时升级或卸载。

## 10. 沙箱边界

生产容器默认使用只读根文件系统、非 root 用户、移除 Linux capabilities、`no-new-privileges`、固定 CPU/内存/PID 限制和仅内存 `/tmp`。插件没有数据库、Redis、宿主目录或 Docker Socket 凭据。

外网请求必须使用运行时注入的标准 HTTP/HTTPS 代理，并匹配清单的域名白名单。代理拒绝未声明域名、私网、回环、链路本地和保留地址，并把拒绝事件写入 WeKnora 审计日志。第一版以 Linux 和 Docker 为生产运行环境，原生进程模式只用于开发调试。

## 11. 常见错误

- `incompatible protocol major versions`：插件和宿主协议主版本不同，升级插件 SDK 或宿主。
- `image must match spec.image`：安装请求镜像与清单不一致。
- `secretFields field ... is not defined`：密钥名未在 Schema 顶层 `properties` 中声明。
- `plugin runtime is disabled`：未设置 `WEKNORA_PLUGIN_RUNTIME_ENABLED=true`，或没有使用 `plugins` profile。
- 健康检查失败：检查容器日志、gRPC 监听端口是否为 `9000`、运行时共享令牌和插件网络。
- 外部 API 请求被拒绝：检查 `permissions.network` 和 `allowedHosts`，不要填写 URL 路径。
- 插件无法卸载：先禁用插件，并移除仍使用其连接器类型的数据源实例。
