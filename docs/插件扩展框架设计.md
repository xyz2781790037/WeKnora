# WeKnora 插件扩展框架设计（第一版）

## 1. 目标

第一版为 WeKnora 建立统一的扩展协议和管理入口，使主仓之外的插件无需修改、重新编译 WeKnora 即可安装和运行。框架覆盖以下四类扩展能力：

- 数据源连接器
- 文档解析器
- 联网搜索引擎
- 模型供应商

四类插件共享清单、版本协商、配置、权限、生命周期、健康检查和审计机制，但使用各自独立的能力接口。GitHub 数据源用于验证完整同步闭环，文档解析、联网搜索和模型供应商也已通过动态适配器接入现有主流程。

## 2. 第一版范围

### 2.1 必须完成

- 外部插件以独立 Docker 容器运行，通过 Protobuf/gRPC 通信。
- WeKnora 主服务不直接操作 Docker，由独立的 `plugin-runtime` 服务管理插件容器。
- 系统管理员通过插件清单和 Docker 镜像地址安装、启停、升级、卸载插件。
- 插件程序全局安装；连接配置、同步游标和数据按租户隔离。
- 现有内置扩展保持原实现，通过适配层进入统一管理，不迁移到独立进程。
- 插件清单声明类型、兼容版本、配置 JSON Schema、网络和数据访问权限。
- 插件容器不能访问 WeKnora 数据库和 Redis，只能通过规定的 gRPC 接口交换数据。
- 插件运行在隔离网络中；未声明网络权限时不能访问外网，受阻访问写入审计日志。
- GitHub 示例插件支持 `github.com` 的公开仓库和 Personal Access Token 私有仓库。
- 一个 GitHub 数据源实例对应一个仓库、一个分支和一个 WeKnora 知识库。
- GitHub 插件只同步指定仓库中的文档文件，不处理 Issue、Pull Request 和 GitHub Wiki。
- 支持手动同步和定时同步；支持新增、修改、删除以及断点续传。
- Go SDK、Go 插件模板和中文开发文档位于 WeKnora 主仓库。
- GitHub 示例插件位于独立仓库 `xyz2781790037/weknora-github-source-plugin`。
- 外部文档解析、联网搜索和模型供应商可在启用时动态进入现有注册表，禁用时移除。
- 系统管理员可粘贴清单或通过公开 HTTPS 清单地址安装、升级插件。
- `pluginctl` 可生成四类 Go 插件骨架，并执行清单校验和本地协议联检。
- 管理页面可读取运行时最近的生命周期、网络与能力调用事件。
- 管理员安装或升级前必须确认清单声明的网络、数据和能力权限。
- 通过清单地址安装的插件支持检查新版本和一键升级，失败时恢复旧运行状态。
- 四类插件配置由统一 JSON Schema 表单生成，并在浏览器、宿主和插件三层校验。
- 主服务定时检查插件健康，连续失败后按冷却策略自动重启。
- 运行时事件持久化到审计日志，并支持按插件、类型、结果和时间查询。
- GitHub 插件市场支持后端搜索、类型与兼容性筛选、分页、缓存和发布者认证标记。
- `pluginctl compat` 由插件脚手架生成的 CI 在 PR 和主分支推送时执行。
- 运行时在能力调用前强制执行清单声明的 `dataAccess` 权限。
- 插件镜像可绑定摘要与可信发布者 Ed25519 签名，生产环境可拒绝未签名镜像。
- 插件可申请不超过运行时上限的 CPU、内存、PID、并发和每分钟调用额度。

### 2.2 暂不实现

- 中心化注册表、用户评分与自动恶意代码审核；当前市场基于 GitHub Topic 发现公开仓库。
- GitHub OAuth、GitHub App、GitHub Enterprise 和 Webhook。
- Windows、macOS 原生插件运行时。
- 无人值守自动升级；当前升级由管理员触发，并在失败时自动回滚。
- 生产级外部文档解析器和模型供应商示例。
- 英文插件开发文档。

## 3. 总体架构

```text
浏览器
  │ REST
  ▼
WeKnora 主服务 ── gRPC ──► plugin-runtime ── gRPC ──► 插件容器
  │                            │                         │
  │ PostgreSQL / Redis         │ Docker API              │ 外部数据源
  ▼                            ▼                         ▼
现有解析、分块和索引流程      隔离网络/资源/审计          GitHub API
```

### 3.1 WeKnora 主服务

主服务负责：

- 保存插件安装记录、状态、清单和镜像版本。
- 校验系统管理员权限。
- 保存租户级数据源配置、密钥和同步游标。
- 根据插件清单动态展示配置表单。
- 将外部数据源插件适配成现有 `datasource.Connector`。
- 接收插件返回的原始文件，复用现有文档解析、分块、索引和删除流程。
- 记录安装、启停、升级、同步和权限拦截审计事件。

主服务不负责拉取镜像、创建容器，也不向插件开放数据库或 Redis。

### 3.2 plugin-runtime

`plugin-runtime` 是独立 Go 服务，负责：

- 拉取指定 Docker 镜像。
- 创建、启动、停止、升级和移除插件容器。
- 为每个插件设置只读根文件系统、非特权用户，以及受全局上限约束的 CPU、内存、PID、并发、频率和调用超时。
- 将插件放入专用内部网络，阻止其直接访问 WeKnora、数据库和 Redis。
- 根据清单决定是否提供受域名白名单约束的外网出口。
- 执行健康检查和协议握手。
- 在启动镜像前核对摘要并验证可信发布者签名。
- 在转发能力请求前检查数据访问权限和调用配额。
- 代理主服务与插件之间的能力调用。
- 记录容器生命周期和被拒绝的网络访问。

`plugin-runtime` 是唯一需要 Docker API 权限的组件，主服务不挂载 Docker Socket。

### 3.3 插件容器

插件容器负责实现公共生命周期服务和至少一种类型能力服务。插件必须：

- 启动 gRPC 服务并返回自身清单。
- 在调用时校验配置。
- 遵守调用上下文的取消与超时。
- 不保存 WeKnora 数据库状态。
- 不记录密钥。
- 将数据源专有概念转换为公共文档模型。

## 4. 公共协议

协议包版本为 `weknora.plugin.v1`。所有插件实现以下公共方法：

- `Handshake`：协商协议版本和宿主版本，并返回镜像内置的插件身份与能力清单。
- `HealthCheck`：返回可用状态和诊断信息。
- `ValidateConfig`：校验租户实例配置，但不持久化配置。

清单至少包含：

- 全局唯一插件 ID，例如 `io.weknora.datasource.github`。
- 名称、描述、插件版本和协议版本。
- 扩展类型与能力列表。
- 兼容的 WeKnora 版本范围。
- Docker 镜像地址。
- 配置 JSON Schema，以及需要保密的字段列表。
- 网络权限开关和域名白名单。
- 允许读取的数据类型。
- 默认单次调用超时。
- 发布者、源码仓库、镜像摘要和可选 Ed25519 签名。
- CPU、内存、PID、最大并发和每分钟调用申请值。

宿主在安装和每次启动时校验清单。协议主版本不兼容时拒绝加载；次版本通过能力协商向后兼容。

## 5. 四类能力接口

### 5.1 数据源插件

数据源插件提供：

- `ListResources`：列出可选择的仓库、空间、目录或页面。
- `ResolveResourceAncestors`：恢复层级选择所需的祖先节点。
- `Sync`：服务端流式返回文档事件和游标检查点。

公共文档事件只表达：

- `UPSERT`：新增或修改文档。
- `DELETE`：删除文档。
- `CHECKPOINT`：一个可安全恢复的游标。

文档包含外部 ID、标题、文件名、MIME 类型、原始字节、来源 URL、更新时间和通用元数据。同步游标是插件自行解释的不透明 JSON，WeKnora 只负责保存并在下次同步时原样传回。

GitHub、Confluence 和本地目录等数据源的差异全部封装在插件内部：GitHub 文件、Confluence 页面和本地文件最终都转换为相同的文档事件。

### 5.2 文档解析器插件

文档解析器插件声明支持的文件类型，并提供双向流式 `Parse` 方法，输入原始文件，输出 Markdown、解析元数据和附件。

### 5.3 联网搜索插件

联网搜索插件提供 `Search`，输入查询、语言、数量和分页参数，输出统一的标题、URL、摘要、来源和发布时间。

### 5.4 模型供应商插件

模型供应商插件提供模型发现以及 Chat、Embedding、Rerank 能力。每种模型能力独立声明，宿主只调用插件明确支持的方法。

## 6. 数据源同步流程

1. 管理员安装并启用 GitHub 插件。
2. 租户管理员在知识库页面创建数据源实例，填写仓库、分支、路径规则和可选 PAT。
3. WeKnora 使用现有加密配置机制保存密钥，API 响应和日志不返回明文。
4. 手动操作或现有定时调度器创建异步同步任务。
5. 外部连接器适配器将配置和上次游标发送给 `plugin-runtime`。
6. `plugin-runtime` 转发给 GitHub 插件，插件流式返回文档事件和检查点。
7. 适配器将事件转换为现有 `types.FetchedItem`，交给 `DataSourceService`。
8. `DataSourceService` 继续使用现有的文档解析、分块、索引、更新和删除逻辑。
9. 检查点由现有数据源仓库保存；中断后从最后检查点恢复。
10. 单个文件失败只写入同步结果，其他文件继续处理。

同一文档使用“数据源实例 ID + 外部文件 ID”进行幂等识别。插件不得生成 WeKnora 内部文档 ID。

## 7. GitHub 增量策略

首次同步读取目标分支的文件树，按包含/排除规则和 WeKnora 支持的扩展名筛选文件，然后逐个下载原始内容。游标保存当前提交 SHA 和已处理进度。

后续同步比较游标提交和当前提交：

- 新增或修改文件输出 `UPSERT`。
- 删除文件输出 `DELETE`。
- 重命名输出旧路径 `DELETE` 和新路径 `UPSERT`。
- 每批完成后输出完整检查点。
- 历史不可比较、分支被强推或游标失效时安全降级为全量扫描。

游标只在检查点成功持久化后推进。重复收到事件由现有幂等逻辑消除，不会产生重复文档。

## 8. 权限隔离

插件容器默认采用：

- 非 root 用户。
- 只读根文件系统。
- 删除全部 Linux capabilities。
- `no-new-privileges`。
- 逐插件 CPU、内存、PID、并发和调用频率上限。
- 仅 `/tmp` 可写且使用内存文件系统。
- 只连接专用内部 Docker 网络。
- 不挂载宿主目录、数据库凭据或 Redis 凭据。

无网络权限的插件只能访问 `plugin-runtime` 的 gRPC 端点，不能获得外网出口。有网络权限的插件必须通过运行时的出口代理，代理按域名白名单放行并记录拒绝事件。

主服务只能通过运行时 gRPC 网关调用插件。运行时根据方法所需的数据类型检查清单 `dataAccess`，未声明时不转发正文、元数据、查询文本或对话内容，并记录拒绝事件。插件的资源申请值只能小于或等于实例管理员配置的全局上限。

安装和升级时，运行时读取 Docker 实际镜像摘要。清单声明供应链信息后，发布者必须存在于实例可信公钥映射中，摘要必须一致，且 Ed25519 签名必须覆盖插件 ID、版本、镜像、发布者、源码仓库和摘要。生产实例可开启严格模式，拒绝未签名插件。

## 9. 持久化模型

新增系统级 `plugins` 表，保存：

- 插件 ID、类型、名称、版本和协议版本。
- 镜像地址和不可变镜像摘要。
- 完整清单。
- 安装、启用、健康和错误状态。
- 安装人、安装时间和更新时间。
- 默认调用超时。

租户级数据源配置继续使用现有 `data_sources` 表。外部数据源的 `type` 使用插件清单声明的连接器类型，通过动态连接器注册表解析到对应插件，避免重复建立同步状态模型。

审计事件继续使用现有 `audit_logs` 表，不创建第二套日志系统。

## 10. 兼容策略

- 现有 `datasource.Connector` 接口和内置连接器不删除。
- 连接器注册表同时容纳内置连接器和外部连接器适配器。
- 现有数据源 API、异步任务、同步日志和前端列表继续工作。
- 统一管理接口把内置扩展标记为 `builtin`，把容器插件标记为 `external`。
- 内置扩展不可卸载，只能按现有规则配置；外部插件由系统管理员管理生命周期。
- 外部插件未安装或不可用时，只影响其对应实例，不阻塞 WeKnora 启动。

## 11. 计划目录

```text
api/proto/plugin/v1/              # 公共 Protobuf 协议
sdk/plugin/go/                     # Go SDK 与服务端辅助代码
sdk/plugin/go/template/            # 最小 Go 插件模板
internal/plugin/                   # 清单、版本、领域模型和注册表
internal/plugin/runtimeclient/     # 主服务到 plugin-runtime 的客户端
internal/plugin/datasource/        # 外部数据源 Connector 适配器
internal/application/repository/   # 插件安装记录仓库
internal/application/service/      # 插件管理服务
internal/handler/                  # 插件管理 REST API
cmd/plugin-runtime/                # 独立运行时进程
internal/pluginruntime/            # Docker 生命周期、隔离和出口代理
frontend/src/views/system/         # 系统插件管理页
docs/                              # 中文开发、部署和安全说明
```

独立示例仓库：

```text
weknora-github-source-plugin/
  cmd/plugin/main.go
  internal/githubsource/
  plugin.yaml
  Dockerfile
  .github/workflows/release.yml
  README.md
  docs/
```

## 12. 验收标准

- 不修改主仓代码即可安装独立 GitHub 插件镜像。
- 能将示例仓库的 `README` 和 `docs` 文件完整同步到指定知识库。
- 修改一个远端文件后，第二次同步只重新处理该文件。
- 删除文件时复用 WeKnora 现有删除行为。
- 同一文件重复同步不产生重复知识条目。
- 同步中断后可从最后检查点继续。
- 一个文件失败不影响其他文件。
- 协议版本不兼容时拒绝启动并显示明确原因。
- 无网络权限测试插件无法访问外网，尝试被记录。
- 非系统管理员无法安装、升级或卸载插件。
- 插件无法连接 WeKnora 数据库和 Redis。
- 仅凭中文文档和 Go 模板可以实现并加载一个最小插件。
